# 山窗手记操作指南

博客用 Hugo 和 PaperMod 构建。平时写文章只需编辑 Markdown，改栏目和首页文案用 `hugo.toml`，改颜色和动效用 CSS。推送源码后，GitHub Actions 会生成并发布静态网页。

## 1. 先打开本地预览

在 PowerShell 中运行：

```powershell
Set-Location 'D:\MY\bk\firstBlog'
$hugo = 'E:\hugo\hugo_extended_0.169.0_windows-amd64\hugo.exe'
& $hugo version
& $hugo server --renderToMemory --noBuildLock --buildDrafts
```

打开 [http://localhost:1313/](http://localhost:1313/)。保存 Markdown、配置或 CSS 后，Hugo 通常会自动刷新。按 `Ctrl+C` 停止服务。预览时用了 `--buildDrafts`，所以草稿也看得到。发布前再去掉这个参数预览一次，确认首页和归档显示的是你打算上线的内容。

换电脑时先克隆项目和 PaperMod 子模块，再安装与工作流相同版本的 Hugo Extended。已有仓库但主题目录为空时，运行 `git submodule update --init --recursive`。

## 2. 想改什么就去哪里

| 想调整的内容 | 文件或配置 |
|---|---|
| 顶部博客名、浏览器标题和站点地址 | `hugo.toml` 开头的 `title`、`baseURL` |
| 搜索引擎里的站点简介 | `[params]` 下的 `description` |
| 首页大标题、简介、诗句、署名和题图 | `[params.homeInfoParams]` |
| 顶部栏目名称、顺序、链接 | `[[menus.main]]` |
| 每页文章数量 | `[pagination]` 下的 `pagerSize` |
| 主题、目录、阅读时间、上一篇和下一篇、代码复制按钮 | `[params]` |
| 某篇文章的标题、日期、摘要、标签和独立选项 | 该文章开头的 `+++` 区块 |
| 首页和导航的字体、配色、留白和动效 | `assets/css/extended/blog.css` |
| 正文、代码块、表格、引用和目录侧栏 | `assets/css/extended/typora.css` |
| 首页标题、诗句、图片的排列方式 | `layouts/_partials/home_info.html` |
| 题图、站点图标等全站共用文件 | `static/` |

用 UTF-8 保存文件。TOML 的配置项归属最近一个表头，比如 `[params]`。找到原来的表头后修改或添加行，同一个表头只写一次。博客改名时，可以同时更新文件开头的 `title` 和首页区块里的 `title`。

### 改首页诗句或题图

打开 `hugo.toml`，修改已有的这段：

```toml
[params.homeInfoParams]
title = "山窗手记"
content = "技术实践、项目笔记与日常随想。"
verse = "行到水穷处，坐看云起时。"
verseSource = "王维《终南别业》"
image = "images/ink-mountains.webp"
```

如果换图，把新图放进 `static/images/`，将 `image` 指向相应文件，比如 `images/new-cover.webp`。路径从 `static/` 里面开始写。当前题图会随屏幕裁切，主体放在右侧可以给左边的标题留空间。清空 `verse` 可以收起诗句和署名，清空 `image` 会保留纯色背景。

### 增加一个顶部栏目

例如要加「关于」，先创建 `content/about.md`：

```markdown
+++
title = "关于"
showToc = false
+++

这里写自我介绍和博客主题。
```

然后在 `hugo.toml` 最后追加：

```toml
[[menus.main]]
name = "关于"
pageRef = "/about"
weight = 60
```

`pageRef` 填 Hugo 内容路径。已有内容一般可以直接用，例如 `/posts` 和 `/archives`。链接到外部网站时，用 `url = "https://example.com/"` 替换 `pageRef`。`weight` 越小越靠前。删掉对应的菜单块只会移除导航链接，原页面仍可通过原地址访问。

### 改目录、主题和样式

下面是当前项目里常用的开关，在已有的 `[params]` 里修改：

```toml
defaultTheme = "auto"
showToc = true
tocOpen = true
showReadingTime = true
showBreadCrumbs = true
showPostNavLinks = true
showCodeCopyButtons = true
```

`defaultTheme` 接受 `auto`、`light`、`dark`。`auto` 默认跟随设备，访客也可以用顶部按钮切换。文章的二级到四级标题会自动进入右侧的「本篇目录」，范围可在 `[markup.tableOfContents]` 下调整。想让某篇文章的桌面目录默认折叠，在它的头部加 `tocOpen = false`。用 `showToc = false` 可以隐藏该篇目录。

左侧显示同主题文章。要把几篇文章放进同一个主题，在它们各自的头部加上 `categories = ["项目实践"]`。有多个分类时取第一个，未设分类时显示所在栏目的文章。窄屏时，左下角的「专题」和右下角的「本篇目录」可分别打开。

正文样式在 `assets/css/extended/typora.css`。浅色用 Typora GitHub 主题的 Open Sans、16px 字号和 1.6 倍行高，深色按 Night 主题配置。Open Sans 字体随站点发布，中文使用设备上的字体回退。

CSS 中的 `--theme` 是页面底色，`--entry` 是文章卡片底色，`--primary` 是主要文字色，`--journal-accent` 是强调色。浅色变量在 `:root`，深色变量在 `:root[data-theme="dark"]`。标题和题诗使用 `--journal-serif` 的本机宋体回退。首页淡入只会在设备允许动效时运行。改模板或样式时，从项目自己的 `layouts/` 和 `assets/` 下入手，便于以后更新主题子模块。

### 搜索、标签和归档

- 搜索页由 `content/search.md` 提供。PaperMod 使用 `[outputs]` 中首页的 `JSON` 输出建立索引，改配置时保留它。
- 标签页来自各篇文章的 `tags`。想把文章归到已有标签下，沿用同一个名字，比如「Java」。
- 归档页由 `content/archives.md` 提供，按文章日期分组。首页和归档通过 `mainSections = ["posts"]` 收录 `content/posts/` 下的文章。

## 3. 新建、编辑和更新文章

### 新建

在项目目录中运行：

```powershell
& $hugo new content posts/my-new-post/index.md
```

打开 `content/posts/my-new-post/index.md`，编辑文件头和正文：

```markdown
+++
title = "我的新文章"
date = "2026-11-12T09:00:00+08:00"
draft = true
description = "这篇文章要解决的问题。"
summary = "这句话显示在文章列表中。"
tags = ["Java", "项目笔记"]
+++

开头写文章的背景。

## 问题是什么

这里写正文。

### 具体做法

这里写步骤。
```

把示例日期换成你的实际日期，准备上线时把 `draft` 改成 `false`。文件夹名会成为文章网址的一部分，建议用小写英文和连字符。标题可以随时改。已发布文章尽量保留文件名和目录，方便旧链接继续访问。

### 放图或插入代码

把文章自己的图放到 `index.md` 同一个文件夹，比如 `architecture.webp`，在正文写 `![服务架构图](architecture.webp)`。这张图会随文章一起发布。可以用 `[cover]` 在头部指定封面，例如在结束的 `+++` 前写：

```toml
[cover]
image = "architecture.webp"
alt = "服务架构图"
```

代码块用三个反引号包起来，并标明语言，比如 `java`、`sql` 或 `powershell`。文章正文用 `##` 起小节，文章标题已经由主题渲染。

### 修改已发布的文章

编辑原 Markdown 即可。可以用 `lastmod = "实际更新时间"` 记录修订时间，保留原来的 `date` 就能维持原有归档日期。需要换网址时，先在文章头部用 `aliases = ["/posts/old-slug/"]` 保留旧入口，再在本地验证旧地址。

## 4. 发布到 GitHub Pages

### 一次性检查 public

`public/` 是 Hugo 的生成目录，GitHub Actions 会重新生成。这个仓库过去提交过其中的文件。先用下面的命令确认 Git 是否仍在跟踪它：

```powershell
git ls-files -- public
```

如果有输出，运行 `git rm -r --cached -- public`，把生成文件移出 Git 索引。这会在下一次提交中删除仓库里的生成文件，本地文件仍在。新版 `.gitignore` 已用 UTF-8 写好 `/public/`，这一步完成后 Git 会忽略该目录。预览时用内存模式，也可以避免生成文件混进提交。

### 构建、提交并推送

1. 检查文章已改为 `draft = false`，用不带 `--buildDrafts` 的预览检查首页、文章页和图片。
2. 在另一个 PowerShell 窗口运行生产构建。先按前文设置 `$hugo`，构建产物放到临时目录中：

   ```powershell
   $buildDir = Join-Path ([IO.Path]::GetTempPath()) ("shan-chuang-" + [guid]::NewGuid())
   & $hugo --minify --panicOnWarning --noBuildLock --destination $buildDir
   ```

3. 查看 `git status --short`。日常发文章时，只添加本次编辑的文章和资源：

   ```powershell
   git add -- content/posts/my-new-post
   git diff --cached --stat
   git commit -m "发布新文章"
   git push origin main
   ```

   如果这次要把整套改版一起发布，按实际改动添加 `hugo.toml`、`.gitignore`、`assets/`、`layouts/`、`static/`、`content/` 和 `docs/`，再检查暂存区。

4. GitHub 仓库的 [Settings → Pages](https://github.com/lightyear88/lightyear88.github.io/settings/pages) 中，发布来源应为 **GitHub Actions**。在 [Actions](https://github.com/lightyear88/lightyear88.github.io/actions) 等 `Deploy Hugo site to Pages` 的 `build`、`deploy` 都成功，再打开 [博客](https://lightyear88.github.io/) 验证。

### 常见问题

| 现象 | 怎么查 |
|---|---|
| 本地看得到，上线后找不到文章 | 检查 `draft`、未来的 `date`、是否提交并推送，以及 Actions 是否成功 |
| 首页 404 | 检查 Pages 的发布来源，打开最近一次 Actions 运行看失败步骤 |
| 构建提示找不到 PaperMod | 检查 `themes/PaperMod` 和子模块是否初始化 |
| 有目录设置，文章里没显示 | 确认正文写的是 Markdown 标题，例如 `## 设计思路` |
| 搜索输入框或搜索结果异常 | 检查首页 `index.json` 是否生成，正文是否设置了 `searchHidden = true` |
| 图片在 Windows 本地能看到，上线后 404 | 核对 Markdown 路径、文件名大小写和图片是否已提交 |
| Git 推送提示远端比本地更新 | 先用 `git status` 确认改动已保存，再同步远端提交并处理冲突，最后重新推送 |
